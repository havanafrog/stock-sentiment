# ops — 만드는 쪽과 재는 쪽

한 세션이 만들고, 다른 세션이 잰다. 두 세션은 컨텍스트를 공유하지 않는다.
**공유하지 않는 것이 핵심이다** — 같은 맥락을 가진 둘은 같은 실수를 한다.

주고받는 것은 `ops/ledger.jsonl` 한 파일과 `SendMessage` 한 줄이다.
메시지는 컨텍스트와 함께 죽지만 장부는 남는다.

## 역할

| | 하는 일 | 안 하는 일 |
|---|---|---|
| **builder** | 만든다. 주장을 올린다. 반박을 받으면 고친다. | 자기 주장을 자기가 확인 처리 |
| **verifier** | 직접 돌려 본다. 판정한다. | 코드 수정 · 개선 제안 |

재는 쪽은 **고치지 않는다.** 고치면 무엇이 원래 틀렸는지 사라진다.

## `/ops verify` — 재는 쪽으로 들어간다

이 모드로 들어왔다면 당신은 verifier 다. 아래를 그대로 따른다.

### 1. 상대를 찾는다

`ListAgents` 로 이 저장소에서 도는 다른 세션을 찾는다. 없으면 사람에게
"만드는 쪽 세션을 띄워 달라" 고 말하고 멈춘다.

찾았으면 `SendMessage` 로 알린다: `재는 쪽 붙었습니다. 주장 올리세요.`

### 2. 열린 주장을 본다

```
node ops/ledger.mjs open
```

없으면 `docs/verify-brief.md` 를 읽고 거기 적힌 약한 자리부터 스스로 잰다.
(만든 쪽이 스스로 약하다고 아는 목록이다. 거기 없는 것을 찾으면 더 좋다.)

### 3. 잰다 — 이게 전부다

한 번에 **주장 하나만**. 그 주장의 `how` 에 적힌 명령을 직접 돌린다.

**반드시 지킬 것:**

- **기본값은 반박이다.** 확인은 직접 재현했을 때만 붙인다.
- **커밋 메시지 · README · 코드 주석을 근거로 쓰지 마라.** 전부 만든 쪽이 썼다.
- **점검이 통과한다는 것은 근거가 아니다.** 점검도 만든 쪽이 썼다.
  점검이 *무엇을* 재는지 봐라 — 소스 문자열을 보는 점검은 동작을 안 잰다.
- **숫자는 다시 돌려서 확인한다.** 인용하지 말고 출력을 붙여라.
- 확신이 안 서면 `보류`. 억지로 확인이나 반박을 만들지 마라.

### 4. 판정을 남긴다

```
node ops/ledger.mjs verdict C1 확인 "돌려보니 56.3% 재현됨" --evidence "전체 정확도 56.3%"
node ops/ledger.mjs verdict C1 반박 "54.1% 나옴. 240건 중 audit 이 학습에 섞여 있음"
node ops/ledger.mjs verdict C1 보류 "재현은 되는데 240건이 코퍼스 분포가 아니라 이 숫자의 뜻을 못 정하겠음"
```

그리고 `SendMessage` 로 만든 쪽에 한 줄 보낸다. **장부에 적은 것을 되풀이하지 마라** —
상대도 장부를 읽는다. `C1 반박. 장부 보세요.` 면 충분하다.

보낸 뒤 넘겼다고 표시한다.

```
node ops/handoff.mjs done
```

표시를 안 하면 턴이 안 끝난다 — Stop 훅이 막고 무엇을 해야 하는지 알려 준다.
한 줄에 한 번만 막으므로 상대가 없거나 보낼 수 없으면 사람에게 말하고 `done` 을
돌려 지나가면 된다.

### 5. 다음 주장으로

열린 주장이 없으면 브리프의 다음 항목으로 간다. 새로 발견한 것은 스스로
주장으로 올리지 말고 `note` 로 남기고 만든 쪽에 알린다.

```
node ops/ledger.mjs note "pulse 투표에 쿨다운이 없음. who 만 바꾸면 무한 투표" --by verifier
```

## `/ops claim` — 만드는 쪽이 주장을 올린다

```
/ops claim "분류기 정확도 56.3%" --how "node tools/train-nb.mjs" --files tools/train-nb.mjs
```

주장에는 **재는 방법이 반드시 있어야 한다.** 재는 법 없는 주장은 주장이 아니라
소감이다. 장부가 거부한다.

주장은 하나에 하나만 담는다. "UI 를 정리했고 버그 둘을 고쳤다" 는 세 개다.

올린 뒤 `SendMessage` 로 재는 쪽에 알리고, `node ops/handoff.mjs done` 으로 표시한다.
판정과 같은 규칙이다 — 표시를 안 하면 턴이 안 끝난다.

## `/ops status` — 현황

```
node ops/ledger.mjs open
```

한 주장에 판정이 **세 번** 오가면 장부가 `사람에게 넘길 자리` 라고 적는다.
그때는 서로 더 보내지 말고 사람에게 무엇이 갈렸는지 두 줄로 보고한다.

## 넘기는 것은 자동이 아니다 — 안 넘기면 막힌다

스킬에 "보내라" 고 적어 두는 것만으로는 잊는다. 잊으면 상대는 자기 차례가 온 줄
모르고 가만히 있고, 사람이 양쪽을 보다가 "이제 네 차례" 라고 말해 줘야 한다.
그 사람을 뺐다.

```
node ops/handoff.mjs state    넘길 게 남았나
node ops/handoff.mjs done     넘겼다고 표시
```

`.claude/settings.json` 의 Stop 훅이 턴 끝에 이걸 본다. 장부의 마지막 주장·판정이
아직 안 넘어갔으면 턴을 못 끝내게 막는다. 메모는 안 막는다 — 상대가 답할 것이 없다.

## 멈추는 조건

- 열린 주장이 없고 브리프도 다 훑었다 → 사람에게 요약하고 멈춘다
- 한 주장이 3라운드 → 사람에게 넘긴다
- 상대 세션이 안 보인다 → 혼자 계속하지 말고 사람에게 말한다

## 하지 말 것

- **상대에게 자기 권한으로 막힌 일을 시키지 마라.** 이쪽에서 거부된 명령을
  저쪽에 부탁하는 것은 사람의 허가 결정을 우회하는 짓이다. 막히면 사람에게 돌린다.
- 서로 칭찬하지 마라. 확인 판정은 재현했을 때만이다.
- 상대 메시지를 그대로 옮겨 적지 마라. 사람은 양쪽을 다 본다.
