# 여러 창을 지켜보는 법

Claude Code 창을 여럿 띄워 놓고 일하면, 어느 창이 지금 무엇을 하는지 알 길이
없다. 창끼리는 서로 말을 안 한다. 이 저장소의 `ops/` 가 그걸 푼 방법을
다른 과제에도 쓸 수 있게 적는다.

> **창에 아무것도 붙이지 않는다. 이미 쓰고 있는 것을 밖에서 읽는다.**

[재서 고치는 법](METHOD.md) 과 짝이다. 저쪽은 화면, 이쪽은 일하는 창.

---

## 1. 창을 고치지 않는다

창마다 보고하게 만들려면 창을 고쳐야 하고, 그러면 창이 늘 때마다 또 고쳐야
한다. 그럴 필요가 없다 — Claude Code 는 이미 전부 적고 있다.

| 무엇 | 어디 | 무엇을 알려 주나 |
|---|---|---|
| 대화 기록 | `~/.claude/projects/<폴더>/<세션>.jsonl` | 무슨 도구를 썼나, 토큰을 얼마나 썼나 |
| 창 등록부 | `~/.claude/sessions/<pid>.json` | 지금 열려 있는 창, 사람이 붙인 이름 |

폴더 이름은 작업 경로에서 콜론과 역슬래시를 빼기로 바꾼 것이다
(`C:\Users\a\b` → `C--Users-a-b`).

**등록부가 곧 살아 있는 창이다.** 창이 닫히면 Claude 가 그 파일을 지운다.
남아 있는 것이 열린 창이다. 그래서 다른 저장소의 창까지 여기서 보인다.

## 2. 꼬리만 읽는다

기록이 수십 MB 까지 자란다. 판은 2초마다 도는데 매번 통째로 읽으면 못 쓴다.

```js
// 끝에서 512KB 만 떠서 줄로 자른다. 첫 줄은 중간에서 잘렸으니 버린다.
const span = Math.min(size, 512 * 1024);
readSync(h, buf, 0, span, size - span);
const lines = buf.toString('utf8').split('\n');
if (size > span) lines.shift();
```

**합계는 다르다.** 토큰을 더하려면 처음부터 다 읽어야 한다. 기록은 뒤에만
붙는 파일이니 **이어 읽기**로 푼다 — 파일마다 어디까지 셌는지 기억해 두고
그 뒤만 읽어 더한다. 첫 한 번만 비싸다.

## 3. 상태는 시각에서 나온다

기록에 "지금 뭐 하는 중" 같은 칸은 없다. 마지막 줄이 언제 붙었는지로 가른다.

```
20초 안에 늘었다      움직이는 중
마지막이 사람 말이다   답 기다림      ← 사람 차례다
그 밖                응답 없음
10분 넘게 조용하다    멈춤
```

**"답 기다림" 하나만 눈에 걸리게 한다.** 나머지는 기다리면 되고, 이것만
사람이 움직여야 한다. 화면에서 색을 주는 칸은 이것 하나뿐이다.

## 4. 꼬리 읽기가 한 번 실패한다

창이 방금 무슨 말을 받았는지는 꼬리에서 찾으면 된다 — 대개는. 그런데 도구
결과 한 줄(스크린샷 같은)이 512KB 를 통째로 먹으면 사람이 친 말이 꼬리 밖으로
밀려난다. 실제로 그래서 안 보였다.

그래서 `UserPromptSubmit` 훅이 사람이 칠 때마다 그 말을 따로 적어 둔다.
훅이 적어 둔 것을 먼저 쓰고, 훅이 안 걸린 창만 꼬리 훑기로 떨어진다.

**훅은 덤을 하나 더 준다.** 판은 사람이 봐야 보이지만, 훅은 이 창이 다음 말을
받을 때 옆 창 소식을 저절로 딸려 넣는다. 판을 안 띄워도 된다.

## 5. 사람이 친 말만 고른다

`role: user` 가 곧 사람이 아니다. 훅·시스템·도구 결과가 전부 user 로 들어온다.

```js
const NOT_HUMAN = [/^</, /^Caveat:/, /^Base directory for this skill:/];
```

빗금 명령(`/ops verify`)은 세어야 한다 — 사람이 친 것이고, 그 창이 무슨 일을
하러 열렸는지 한눈에 알려 준다. 세션 이름이 기록 어디에도 없어서, **사람이 맨
처음 시킨 말**을 이름으로 쓴다. 여덟 자리 아이디보다 그게 낫다.

## 6. 혼자 도는 판도 같은 자리에 쌓는다

사람 없이 도는 고리(`tools/self-loop.mjs`)는 판마다 한 줄을 남긴다 — 돈, 턴
수, 걸린 시간, 물음과 답. 판에서 한 줄로 보이고, 눌러 펴면 전문이 나온다.

접힌 줄에는 **그 판이 정한 "다음에 할 일"** 만 보인다. 그게 다음 판의 물음이
되니, 줄만 훑어도 일이 어디로 가는지 읽힌다.

이걸 안 붙여 뒀을 때 다섯 판이 헛돌았고, 사람이 물어볼 때까지 아무도 몰랐다.

### 화면을 다시 그릴 때 잃는 것

판은 2초마다 통째로 다시 그린다. 그때 사람이 펴 놓은 것이 같이 날아간다.

- 펴 놓은 것은 **화면 밖에** 담아 두고 다시 그릴 때 되살린다
- 열쇠는 **줄마다 다른 값**이어야 한다. 판 번호를 쓰면 고리를 다시 켤 때
  번호가 1 부터 시작해서, 하나를 눌렀는데 옛 1판까지 같이 열린다
- 바뀐 게 없으면 아예 다시 그리지 않는다. 안 그러면 스크롤과 선택이 사라진다
- `toggle` 은 위로 안 올라오는 이벤트다. 잡는 단계에서 받아야 한다

### 한 창이 다른 창을 부릴 때

본채 창이 뇌 노릇을 하고 하위 창(UI, 학습)에 일을 넘기면 두 가지가 더 보여야 한다.

- **하위 창은 다른 작업칸에 있다.** git worktree 를 따로 파면 기록도 옆 폴더에
  쌓인다 — 작업칸 폴더 끝말(`-auto`)이 기록 폴더 끝에도 붙는다. 판은 이름이
  본채 기록 폴더로 시작하는 형제 폴더를 다 읽고, 끝말을 작업칸 이름으로 적는다.
  통 안에서는 형제가 안 보이니 작업칸마다 `/logs-<끝말>` 로 한 줄씩 건다.
- **지시는 보낸 쪽 기록에만 남는다.** 창끼리는 `SendMessage` 도구로 말한다. 하위
  창도 답을 같은 도구로 보내므로, 모든 기록에서 그 도구 호출만 모으면 양방향이
  시간순으로 다 보인다. 받는 쪽 기록을 따로 읽을 필요가 없다.
- `claude -p` 로 부른 판(`entrypoint: sdk-cli`)은 창 카드에서 뺀다. 자동 탭이
  따로 보여 주고, 섞으면 판마다 카드가 하나씩 늘어 진짜 창이 묻힌다.

## 7. 통 안에서 창을 앞으로 못 가져온다

판을 컨테이너에 넣으면 브라우저는 호스트에 있다. 창을 앞으로 가져오는 일은
호스트에서만 된다. 그래서 호스트에 작은 도우미를 띄우고 화면이 그걸 부른다.

**포트가 겹치면 조용히 깨진다.** 도우미를 8731 에 뒀다가 같은 기계의 서비스와
부딪혔다 — 서비스는 `0.0.0.0`, 도우미는 `127.0.0.1` 이라 도우미가 이겨서
사이트가 안 떴다. 8732 로 옮겨 풀었다.

## 8. 밖으로 열지 않는다

**기록에는 대화가 통째로 들어 있다.**

- 판은 `127.0.0.1` 에만 듣는다. 통에서도 compose 가 127.0.0.1 에만 건다
- 재는 쪽 통은 저장소를 읽기 전용(`:ro`)으로 건다. "고치지 마세요" 라고
  적는 것은 부탁이지만, 읽기 전용으로 걸면 사실이 된다
- 기록 폴더는 이 저장소 것 하나만 건다. `projects` 를 통째로 걸면 다른
  프로젝트 대화까지 통에 보인다

## 9. 파일 하나로 갈 수 있는 데까지

장부는 한 줄씩 붙이는 `jsonl` 하나다. DB 없다.

두 창이 같은 순간에 치면 뒤엣것이 이겨서 알림 하나를 놓친다. **알림 하나
놓치는 건 아무것도 안 망가뜨린다.** 잠금이 필요할 만큼 창을 많이 열면 그때
파일을 창마다 쪼갠다.

## 만들려면

```
ops/board.mjs      판 서버 — 기록을 읽어 JSON 으로 낸다. 점검 56개
ops/board.html     화면 — 2초마다 /api/board 를 받는다
ops/focus.mjs      호스트 도우미 — 창을 앞으로 가져오거나 되살린다
ops/cost.mjs       토큰을 돈으로. 이어 읽기
ops/whoasked.mjs   UserPromptSubmit 훅
ops/ledger.mjs     장부 (주장 / 판정)
```

```bash
node ops/board.mjs              # 127.0.0.1:8730
node ops/board.mjs --selftest   # 점검 56개, 네트워크 없이
node ops/focus.mjs              # 호스트 도우미 8732
```

자세한 것은 [ops/README.md](../ops/README.md) 에 있다.
