# 재서 고치는 법

이 저장소에서 화면을 고칠 때 쓴 방법을 다른 과제에도 쓸 수 있게 따로 적는다.
특별한 도구는 없다. 규칙 두 개뿐이다.

> **눈으로 본 것은 근거가 아니다. 잰 것만 근거다.**
> **한 판에 한 가지만 고친다.**

실제로 이 방법으로 폰 화면에서 차트 시작 위치를 600px 에서 395px 로,
봉 높이를 221px 에서 380px 로 옮겼고, 그 과정에서 "고쳤다고 보고했지만
사실은 안 먹고 있던" 수정 두 개를 잡아냈다.

---

## 1. 왜 눈으로 보면 안 되나

세 번 속았다. 전부 화면은 멀쩡해 보였다.

| 보인 것 | 실제 | 어떻게 잡았나 |
|---|---|---|
| 탭 줄이 잘 붙어 있다 | `top: env(safe-area-inset-top)` 이 뒤 규칙에 덮여 죽어 있었다. 노치 밑에 깔림 | 버튼 윗변을 쟀다 — 0px 이어야 할 자리가 아니었다 |
| 접었더니 자리가 줄었다 | 크롬 153 의 `::details-content` 상자 때문에 오히려 92px 세 줄로 무너졌다 | 접기 전후 높이를 쟀다 |
| 짚으면 값이 뜬다 | 뜨긴 뜨는데 떼는 순간 사라진다. 짚고 있는 동안은 손가락이 그 봉을 가린다 | 뗀 직후 딱지 `opacity` 를 쟀다 |

셋 다 **사람 눈에는 정상으로 보이는 고장**이다. 특히 마지막은 마우스로는
절대 안 나타난다 — 커서는 화면을 안 가리고, `pointerleave` 도 밖으로 나갈
때만 온다.

## 2. 한 판의 모양

```
1. 잰다        고치기 전 수치를 먼저 적는다
2. 하나 고친다  한 판에 한 가지
3. 다시 잰다   같은 자리를 같은 방법으로
4. 시험한다    자동 시험 전부 통과해야 한다
5. 딴 데 본다  이번에 안 건드린 화면 폭도 같이 잰다
6. 커밋한다    왜 고쳤는지, 잰 값과 함께
```

5번이 빠지면 폰을 고치다 데스크톱을 부순다. 이 저장소는 매 판
1280×900 을 같이 쟀고, 그래서 "폰만 바뀌고 데스크톱은 그대로" 를
말이 아니라 수치로 댈 수 있었다.

## 3. 재는 도구

브라우저 하나면 된다. 크롬을 디버그 구멍을 열어 띄우고, 코드가 직접 붙는다.

```bash
chrome --headless=new --remote-debugging-port=9222 --user-data-dir=<빈 폴더> about:blank
```

```js
// 붙어서 폰 크기로 만들고, 손가락도 흉내 낸다
await send('Emulation.setDeviceMetricsOverride', { width: 390, height: 844, deviceScaleFactor: 2, mobile: true });
await send('Emulation.setTouchEmulationEnabled', { enabled: true, maxTouchPoints: 5 });
await send('Emulation.setCPUThrottlingRate', { rate: 4 });       // 느린 폰
```

재는 값은 늘 같은 네 가지였다.

| 무엇 | 왜 |
|---|---|
| `getBoundingClientRect().top` / `.height` | 자리와 크기. 첫 화면 안에 드는지가 여기서 갈린다 |
| `documentElement.scrollWidth` vs `innerWidth` | 가로로 삐져나가면 두 값이 갈린다 |
| `document.querySelectorAll('*').length` | 요소 수. 느린 폰에서는 이게 곧 시간이다 |
| `PerformanceObserver({entryTypes:['longtask']})` | 어디서 멈칫하는지 |

**흉내 내서 재는 것**이 특히 값어치 있었다. 종목이 6개일 때는 한 줄에
들어가지만 12개면 두 줄이 된다. 12개를 꽂아 놓고 재니 81px 이 나왔고,
그래서 아직 안 생긴 고장을 미리 고쳤다.

## 4. 시험으로 남긴다

눈으로 멀쩡한데 손가락이 안 닿는 고장은 사람이 못 지킨다. 좌표로 눌러
보는 시험을 저장소에 남긴다.

```
tools/chart-touch-test.mjs   확대·축소·끌기 6개
tools/phone-flow-test.mjs    손가락 동선 5개
```

`Input.dispatchTouchEvent` 로 진짜 좌표를 누른다. 클릭 흉내가 아니다.

**함정**: 한 창에서 터치 흉내를 켜면 그 뒤로 `pointer: coarse` 가 계속
참이다. 데스크톱 검사를 같은 창에서 하면 폰 문구가 나오고 시험이
거짓으로 통과한다. **화면 종류마다 창을 새로 연다.**

## 5. 혼자 돌리기

사람이 매번 붙어 있지 않아도 위 절차가 돌아가게 한 것이 `tools/self-loop.mjs` 다.
한 판의 **답이 다음 판의 물음**이 된다.

```
node tools/self-loop.mjs --dir <작업칸> --file <첫 물음> 900
```

- 대화는 `-c` 로 이어진다. 앞판을 다시 설명하지 않는다
- 답 끝에 "다음 판에 할 일" 과 "남은 대기열" 을 적게 한다 — 그게 다음 물음이니
  그래야 순서가 판을 넘어 산다
- 판마다 `self-loop.jsonl` 에 돈·턴 수·시간·물음·답을 남긴다
- 답이 비거나 `없음` 이면 멈춘다

**따로 둔다.** `git worktree` 로 브랜치와 폴더를 갈라 사람과 같은 파일을
만지지 않게 한다. `push` 는 열지 않는다 — 커밋까지만 하고 사람이 보고 합친다.

**막혔을 때 물어보게 한다.** "폰에서 무엇을 먼저 보일까" 같은 건 치수 문제가
아니라 결정이다. 그럴 땐 답 맨 위에 `사람 필요` 를 적고 멈추게 한다.
실제로 그렇게 멈춰서 물어 왔고, 답을 받은 다음 판에 목표치(332px → 284px)를
정확히 맞췄다.

### 처음 세운 것이 네 번 부러졌다

기록해 둔다. 같은 데서 또 막힐 사람이 있다.

| 막은 것 | 증상 |
|---|---|
| 편집 권한만 열고 시험 권한을 안 엶 | 다섯 판을 "requires approval" 만 적고 돎 |
| 따로 둔 폴더에 데이터가 없어 서버를 못 띄움 | 고친 화면을 볼 방법이 없음 |
| `--allowedTools` 가 뒤에 온 프롬프트를 삼킴 | `Input must be provided ...` 로 죽음 |
| `.bat` 에 실행 비트가 없음(OneDrive) | git bash 가 없는 파일 취급, `exit 127` |

배치를 버리고 `node` 로 다시 썼다. cmd 는 따옴표(`\"` 는 탈출이 아니다)와
글자표(`chcp` 를 파일 중간에서 부르면 주석까지 명령으로 튄다)에서 세 번 깨졌다.

# 기능을 가르는 법

무엇을 따로 떼어낼지 정하는 기준. 이것도 다른 과제에 그대로 쓴다.

## 쪼개는 기준은 "같이 죽는가" 다

코드가 길어서, 파일이 커서 쪼개는 게 아니다. **한쪽이 죽을 때 다른 쪽도
같이 죽어야 할 이유가 없으면** 그때 가른다.

이 저장소에는 그런 자리가 딱 하나 있었다.

```
긁는 일 (수집)  ←→  보여 주는 일 (서빙)
```

토스가 IP 를 막았을 때 화면까지 같이 죽었다. 붙어 있어서 같이 죽은 것이다.
같은 이미지를 두 번 띄우고 데이터 폴더를 함께 쓰면, 한쪽이 막혀도 다른
쪽은 마지막 데이터로 계속 산다.

## HTTP 로 쪼개는 것은 대개 손해다

"기능별로 나눈다" 는 말이 곧 "API 로 나눈다" 는 뜻은 아니다.

| | 지금 (파일로 주고받음) | API 로 쪼개면 |
|---|---|---|
| 주고받는 비용 | 파일 읽기 | 직렬화 + 네트워크 홉 |
| 메모리 | 한 몫 | 두 몫 (1GB 서버에서는 이게 아프다) |
| 고장 날 자리 | 없음 | 연결, 시간 초과, 재시도, 버전 |

**조각들이 이미 파일로 주고받고 있으면 그대로 둔다.** 나눌 것은 코드가
아니라 **프로세스**다. 같은 이미지, 다른 명령, 공유 볼륨.

## 가르기 전에 물을 것 셋

1. **따로 죽어도 되나?** 아니면 붙여 둔다.
2. **따로 옮길 일이 있나?** 수집만 다른 기계로 보낼 수 있으면 가른 값을 한다.
3. **따로 배포할 일이 있나?** 수집만 재시작할 때 화면이 안 끊기면 그만큼이 이득이다.

셋 다 아니면 안 가른다. 하나라도 그렇다면, **코드가 아니라 실행 단위를**
가른다.

## 나눌 때 같이 봐야 하는 것

- **쓰는 쪽은 하나만.** 두 프로세스가 같은 파일에 쓰면 그게 새 고장이다.
  이 저장소에서 시험용 서버를 띄울 때는 폴링을 하루로 밀어 사실상 껐다 —
  두 서버가 같은 곳을 두드리면 IP 가 또 막힌다.
- **읽는 쪽은 읽기 전용으로 건다.** 규칙으로 부탁하지 말고 마운트로 막는다.
  `ops/docker-compose.yml` 이 저장소를 `:ro` 로 거는 것이 그 이유다.
- **경로를 한 곳에 모은다.** 쓰기가 일어나는 자리가 흩어져 있으면 볼륨을
  여러 개 걸어야 하고 그건 잘 깨진다 (`paths.mjs` 참고).
