# 검증 브리프

이 문서는 **이 저장소를 처음 보는 세션**에게 주는 지시문입니다. 앞선 세션이 만든
것을 그 세션의 설명에 기대지 않고 다시 재기 위한 것입니다.

읽는 사람에게: 아래 "믿지 마세요" 항목은 만든 쪽이 스스로 약하다고 아는 자리입니다.
여기부터 보면 빨리 값이 나옵니다. 목록에 없는 것을 찾으면 그게 더 좋습니다.

## 규칙

- **커밋 메시지와 README 를 근거로 쓰지 마세요.** 둘 다 만든 쪽이 썼습니다.
  숫자는 직접 다시 돌려서 확인하세요.
- **점검이 통과한다는 것은 근거가 아닙니다.** 점검도 만든 쪽이 썼습니다.
  점검이 무엇을 재는지를 보세요 — 아래 3번 항목입니다.
- 고치지 말고 **재기만** 하세요. 고치면 무엇이 원래 틀렸는지 알 수 없게 됩니다.

## 믿지 마세요 — 만든 쪽이 아는 약한 자리

### 1. 사람 정답지 240건을 한 사람이 찍었습니다

`docs/labels-audit-240.json` 의 `y` 는 전부 한 명(앞선 세션)이 붙였습니다.
두 번째 평가자가 없습니다. 짧은 한국어 글이라 갈리는 자리가 많고, 붙인 쪽도
동전 던지기였다고 적어 둔 글이 여럿 있습니다. 예를 들어:

```
지난주처럼 또 음전으로 끝나진않겠죠? 오늘은 믿어볼렵니다ㅜ    → 긍정으로 찍음
그냥 믿는 수 밖에                                          → 중립으로 찍음
1퍼센트 양전마감이라도 해줘 제발                            → 부정으로 찍음
힘 빠지지말고 양전 마감해줘                                 → 긍정으로 찍음
제발 오늘 그냥 딱 25프로만 오르자;;                         → 부정으로 찍음
```

마지막 셋은 같은 꼴인데 다르게 찍혔습니다. **표본에서 30건쯤 골라 독립적으로
찍고 일치율을 재 보세요.** 일치가 80% 아래면 56.3% 라는 숫자의 오차 막대가
±5%p 보다 훨씬 큽니다.

### 2. 240건은 코퍼스 분포가 아닙니다

SLM 라벨 기준으로 P·N·X 를 80건씩 뽑았습니다. 실제 글은 그 비율이 아닙니다.
그래서 이 240건의 "정확도" 는 **실제 글에서의 정확도가 아닙니다.** 두 채점기를
견주는 자로는 쓸 수 있지만 절대값으로 읽으면 안 됩니다. 이 구분이 README 와
사용법 화면에서 충분히 지켜지고 있는지 봐 주세요.

### 3. 점검 상당수가 소스 문자열을 봅니다

`test/run-live-tests.mjs` 의 R·T·U 절은 `live.html` 을 문자열로 읽어
`src.includes(...)` 로 잽니다. 이건 **동작이 아니라 코드 모양**을 재는 것입니다.
코드를 같은 뜻으로 다르게 쓰면 깨지고, 뜻이 바뀌어도 모양이 같으면 통과합니다.

특히 이 둘은 실제 효과를 전혀 안 잽니다:

- `'무거운 일은 다음 프레임에'` — rAF 두 겹을 쓴다는 것만 확인합니다.
  탭 전환이 실제로 부드러워졌는지는 아무도 안 쟀습니다.
- `'컨트롤 줄에 판때기가 없다'` — CSS 선언에 `background` 가 없다는 것만 봅니다.

### 4. 곡소리 지수는 한 번도 독립적으로 검산되지 않았습니다

`index = clamp(50 + 20z, 0, 100)`, `z = (k − μ)/σ`, μ·σ 는
(종목 × 미 동부 시각 × 봉 길이) 마다 따로 냅니다. `build.mjs` 의 `fearBaseline`·
`countBaseline` 과 `server.mjs` 의 `fearSeries` 가 **같은 정의를 쓰는지** 확인해
주세요. 둘이 어긋나면 화면 숫자와 기준선이 다른 것을 재게 됩니다.

작은 손 계산 하나면 충분합니다. 글 몇 개를 직접 세어 z 를 손으로 내고 화면
숫자와 맞춰 보세요.

### 5. 투표는 막을 방법이 없습니다

`data/pulse.jsonl`. `who` 는 브라우저가 만든 문자열이고 서버는 그대로 믿습니다.
localStorage 를 지우면 새 사람이 됩니다. 기분(mood)에는 30초 쿨다운이 있지만
**투표(vote)에는 아무 제한이 없습니다** — 같은 사람이 who 만 바꾸면 무한히
투표할 수 있습니다.

이게 의도된 것인지, 그리고 이 투표를 나중에 "사람 라벨" 로 학습에 쓸 계획이
있는지 함께 보세요. 오염된 라벨로 학습하면 앞의 모든 숫자가 무너집니다.

또 이 파일은 줄이 계속 쌓이기만 하고 접히지 않습니다. `readPulse()` 가 매번
전체를 훑습니다.

### 6. 접근키가 URL 에 있습니다

`?k=...`. 프록시 로그·브라우저 기록·리퍼러에 남습니다. `data/.access-key` 를
지우고 재시작하면 새로 나오지만, 유출 경로 자체는 그대로입니다.
`server.mjs` 의 `PUBLIC` 집합에 키 없이 나가는 파일이 무엇인지 확인해 주세요.

### 7. `model.json` 이 1.8MB 이고 공개 저장소에 있습니다

`docs/labels-*.json` 에서 다시 만들 수 있는 파일입니다. 서버 메모리는
실측 109MB / 700MB 였습니다. 재현 가능한지 확인해 주세요 —
`node tools/train-nb.mjs --full /tmp/m.json` 을 돌려 지금 것과 어휘 수가
같은지 보면 됩니다. 다르면 커밋된 모델이 코드와 안 맞는 것입니다.

### 8. `normalize()` 가 공백과 숫자를 지웁니다

`시1발 → 시발` 을 살리려는 것인데, 부작용으로 `먹고 아침 → 먹고아침`(고아),
`먹고 고민 → 먹고고민`(고고) 같은 헛매치를 만듭니다. 사전에서는 그 두 낱말을
뺐지만 **분류기는 같은 `normalize` 위에서 n-gram 을 뽑습니다.** 분류기가 이
인공물을 학습했는지는 아무도 안 봤습니다.

## 없는 것

- 사람이 두 명 이상 찍은 라벨
- 실제 코퍼스 분포에서의 정확도
- 탭 전환·차트 그리기의 실측 프레임 시간
- 곡소리 지수의 예측력 검증 (지수가 튄 뒤 주가가 어떻게 됐는지)
- 부하 시험 (1GB 서버, 5초 폴링, 글 70만 건)
