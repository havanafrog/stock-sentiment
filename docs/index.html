토스증권 종목 커뮤니티의 말을 채점해 공포지수로 바꾸고, 같은 시간축의 봉 차트 옆에 놓습니다.

키가 붙은 링크로 한 번 열면 그다음부터는 주소만으로 들어갑니다. 키 없이 오면 전부 404 입니다.

세는 방식이 다릅니다

말을 세는 도구는 많습니다. 대부분 언급 횟수나 강세·약세 비율을 냅니다. 이것은 공포 글의 개수가 평소보다 얼마나 이상한지를 잽니다.

k     = 그 봉이 덮는 구간에 온 공포 글 수
μ, σ  = 그 종목 · 그 미 동부 시각 · 같은 봉 길이의 평소 공포 글 수

z          = (k − μ) / σ
공포지수    = clamp(50 + 20z, 0, 100)      50 = 평소 · 90 = 경보

비율이 아니라 개수입니다. 글 셋 중 둘이 공포인 판과, 글 사백 중 백이 공포인 판은 같은 사건이 아닙니다. 비율은 둘을 못 가릅니다.

시간대마다 기준선이 따로입니다. 한국시간 23시 30분(뉴욕 개장)의 게시판과 아침 8시의 게시판은 원래 다른 곳입니다. 같은 자로 재면 개장마다 경보가 울립니다.

어떻게 만들어졌나

실행할 때 LLM을 쓰지 않습니다. 채점은 글자 n-gram 나이브 베이즈이고, 모델이 없으면 단어 사전으로 돌아갑니다. API 키도 토큰 비용도 없습니다. 의존성 없는 Node 하나입니다.

자가 둘입니다. 라벨 15,813건 중 대부분은 작은 모델이 찍었습니다. 그 정답지로만 재면 "모델을 얼마나 잘 흉내내나"를 재는 것이라, 240건을 라벨을 가리고 사람이 다시 읽어 따로 두었습니다 — 어느 모델도 그건 학습에 쓰지 않습니다.

node fetch-comments.mjs   → data/{티커}.posts.json   글 원문 (증분)
node build.mjs            → data.js                   일봉 + 채점 + 기준선
node server.mjs           → http://localhost:8731     실시간 서버

서버가 왜 필요한가. 토스 API가 Origin 헤더가 붙은 요청을 거절하는데, 브라우저는 교차 출처 요청에 그걸 반드시 붙입니다. 그래서 정적 호스팅만으로는 시세도 글도 못 받습니다. Node가 대신 부르고 결과만 넘깁니다.
