# 실시간 커뮤니티 온도

토스증권 종목 커뮤니티에서 오가는 말을 채점해 **공포지수**로 바꾸고, 같은 시간축의 봉 차트 옆에 놓는 도구입니다.

LLM을 쓰지 않습니다. 채점은 단어 사전이고, API 키도 토큰 비용도 없습니다.

```
node fetch-comments.mjs   →  data/{티커}.posts.json   글 원문 (증분, 처음만 40~60분)
node build.mjs            →  data.js                   일봉 + 채점 + 기준선 (몇 초)
node server.mjs           →  http://localhost:8731     실시간 서버
```

## 화면

한 페이지에 네 탭입니다.

| 탭 | 내용 |
|---|---|
| **메인** | 종목 판 — 현재가·등락·거래량(전일비)·거래대금·체결강도·곡소리. 머리글로 정렬, 줄을 누르면 실시간으로 |
| **실시간** | 1/10/60분·일봉 차트, 이동평균 20·120·200, 곡소리 지수·MACD, 최근 1시간 글 |
| **분석** | 수집 기간 전체를 표로. CSV 내려받기 |
| **글** | 모아둔 글 검색·필터 (감정·기간·좋아요순) |
| **사용법** | 계산식 전부 |

봉 차트는 휠로 확대, 끌어서 이동, 더블클릭으로 초기화합니다. 공포지수 차트가 같은 격자를 쓰므로 세로선 하나로 둘을 같이 짚습니다.

## 공포지수

비율이 아니라 **개수**로 냅니다.

```
k     = 그 봉이 덮는 구간에 온 공포 글 수
μ, σ  = 그 종목 · 그 미 동부 시각 · 같은 봉 길이의 평소 공포 글 수

z          = (k − μ) / σ
공포지수    = clamp(50 + 20z, 0, 100)      50 = 평소 · 90 = 경보
```

1분봉은 글이 중앙값 2건이라 비율이 0% / 50% / 100% 셋뿐입니다. 표본 문턱을 걸면 97%가 빈칸이 됩니다. 짧은 구간에서 실제 신호는 "몇 %가 공포냐"가 아니라 "공포 글이 몇 개 쏟아졌냐"입니다.

기준선을 만들 때 두 가지를 지킵니다.

- **글이 하나도 없는 칸도 0으로 셉니다.** 빼면 평균이 부풀려집니다 (SNDK 미 동부 10시 1분봉: 포함 0.60 · 제외 1.59).
- **주말은 뺍니다.** 넣으면 평일 같은 시각이 늘 높아 보입니다 (0.60 → 0.45).

시각별 기준선이 필요한 이유는 한국 사용자가 쓰기 때문입니다. 같은 SNDK 1분봉인데 미 동부 10시(한국 23시) 0.60건, 14시(한국 새벽 3시) 0.10건입니다.

자세한 건 화면의 `사용법` 탭에 있습니다.

## 감정 점수

글자 n-gram 나이브 베이즈로 긍정·부정·중립을 가릅니다. `model.json`이 있으면 이걸 쓰고,
없으면 아래 사전으로 돌아갑니다. 둘 다 `lexicon.js`가 들고 있어 브라우저와 Node가 같은 걸 씁니다.

학습은 라벨 15,813건 — EXAONE 3.5 7.8B이 찍은 것 + 사람이 읽고 찍은 것.
특징은 글자 1~2-gram, 글마다 한 번씩만 셉니다(반복은 강조지 증거가 아닙니다).

### 자가 둘입니다

SLM 정답지로 재면 "SLM 을 얼마나 잘 흉내내나" 를 재는 것입니다. 정답지 자체가 맞는지는
못 잽니다. 그래서 정답지에서 P·N·X 80건씩 뽑아 라벨을 가리고 사람이 읽어 다시 찍었습니다
— `docs/labels-audit-240.json`. 이 240건은 어느 모델도 학습에 쓰지 않습니다.

**SLM 정답지로 잰 것** (홀드아웃 11,442건)

| | 사전 | 분류기 |
|---|---|---|
| 부정 F1 | 45.5% | **72.9%** |
| 긍정 F1 | 41.0% | **55.0%** |
| 정확도 | 42.0% | **62.3%** |

**사람이 읽고 찍은 것으로 잰 것** (240건)

| | 사전 | 분류기 | SLM |
|---|---|---|---|
| 부정 F1 | 38.2% | 62.2% | **71.7%** |
| 긍정 F1 | 40.0% | 58.4% | **72.0%** |
| 정확도 | 43.8% | 56.3% | **68.8%** |

**이 240건은 실제 글 분포가 아닙니다.** SLM 라벨 기준으로 P·N·X 를 80건씩 고르게 뽑았고,
실제 글은 그렇게 안 옵니다 — 홀드아웃 11,442건에서 P 26.2% · N 51.9% · X 21.8% 입니다.
그 비율로 다시 맞추면 이렇습니다.

| | 사전 | 분류기 | SLM |
|---|---|---|---|
| 균등 표본 240건 | 43.8% | 56.3% | 68.8% |
| 실제 분포로 다시 맞춤 | 39.9% | **61.5%** | 71.6% |

이 되맞춤은 추정입니다 — 층을 SLM 라벨로 잡고 홀드아웃을 코퍼스 대신 썼습니다. 사람 라벨
기준의 실제 분포는 아직 아무도 안 셌습니다.

읽어야 할 순서는 이렇습니다.

- 분류기는 사전보다 확실히 낫습니다 (39.9% → 61.5%). 이 순서는 두 자에서 같습니다.
  균등 표본은 이 차를 12.5%p 로 줄여 보이지만 실제 분포에서는 21.6%p 입니다 — 중립을
  고르게 섞어 놓으면 아무 글에나 X 를 찍는 사전이 실제보다 잘해 보입니다.
- 그러나 **62%는 정확도가 아니라 SLM 흉내 점수입니다.** 사람 자로 잰 값은 61.5% 이고,
  두 숫자가 비슷한 것은 우연입니다.
- 분류기는 선생보다 10.1%p 못합니다. 증류에서 잃은 값입니다. SLM 을 서버에 올릴 수 없어
  치른 값이기도 합니다 — 1GB 서버는 5초마다 채점해야 합니다.
- **분류기는 부정을 과하게 부릅니다.** 부정 정밀도가 사람 자에서 53.0% 입니다. 사람이
  중립으로 본 63건 중 30건을 부정으로 불렀습니다.

사전이 65%를 "걸린 단어 없음"으로 흘려보내던 자리가 14%로 줄었습니다.
흘려보내던 글의 3분의 2는 부정이었습니다.

### 정답지가 틀리는 자리

240건을 읽으면서 SLM 이 어디서 틀리는지가 두 가지로 모였습니다.

**낱말이 문맥을 이깁니다.** 상승 낱말이 있으면 화자가 괴로워도 긍정으로 봅니다.

```
그만 빌빌거리고 좀 올라가자 하        → SLM 긍정
제발 오늘 그냥 딱 25프로만 오르자;;    → SLM 긍정
더 쳐 올려 양전좀 해라..그래야 우리도 널 믿지  → SLM 긍정
```

반대로 욕설과 눈물이 있으면 부정으로 봅니다.

```
속슬 출발했다 빨리가자 시.발아         → SLM 부정   (욕은 감탄입니다)
8월은 불이였으면 ㅠㅠ                  → SLM 부정   (바람입니다)
마이너스가 줄어든것만으로도 행복하네   → SLM 부정   ("행복"이라 적혀 있습니다)
```

사전이 하던 실수와 같은 종류입니다.

**포지션 방향을 못 읽습니다.** 숏·인버스 문맥에서 "올라가라" 는 부정인데 긍정으로 봅니다.

```
좀 올라가봐 숏 좀 싸게 사게            → SLM 긍정
샌디 숏은 가치투자                     → SLM 긍정
응 안 낚 여 4주째 숏 홀딩이야^^        → SLM 긍정
```

그리고 SLM 이 가장 약한 자리는 중립입니다 — 중립 정밀도 55.0%. 중립이라 찍은 80건 중
36건이 실제로는 감정이 있는 글이었습니다(부정 20 · 긍정 16). 애매하면 중립으로 던집니다.

```
s = P(긍정) − P(부정)      중립으로 판정하면 0
```

**공포지수는 그대로 사전입니다.** 공포어에는 라벨이 없어 학습할 자료가 없습니다.
`hasFear`도, 곡소리 지수도 안 바뀝니다.

### 사전 (모델이 없을 때)

`lexicon.js`의 사전에 걸린 단어만 셉니다. 긍정 34개·부정 34개, 가중치 1~3.

```
s = clamp( Σ(부호 × 뒤집기 × 가중치) / (걸린단어수 × 2.2), −1, +1 )

부호     긍정 +1 · 부정 −1
뒤집기   단어 직전 4글자에 안 / 못 / 없 / 아니 가 있으면 −1
걸린 단어가 없으면 0 (중립. "부정"이 아님)
```

브라우저와 Node가 같은 `lexicon.js`를 읽습니다. 한쪽만 고치면 화면 점수와 수집 점수가 갈립니다.

## 라벨 찍기

사전은 부정을 정밀도 67%로 맞히지만 재현율이 34%입니다. 셋 중 둘을 놓칩니다.
어디서 놓치는지는 글을 직접 봐야 알 수 있어서, 글 탭에서 바로 찍습니다.

`라벨`을 켜면 글마다 **긍정·중립·부정** 세 버튼이 붙고 사전이 뭐라 했는지가 옆에 나옵니다.
어긋나면 빨갛게 표시됩니다. 글을 누르고 <kbd>1</kbd>·<kbd>2</kbd>·<kbd>3</kbd> 을 찍으면
저장되고 다음 글로 넘어갑니다. 같은 버튼을 다시 누르면 무릅니다.

보기는 네 가지입니다.

| 보기 | 쓸 자리 |
|---|---|
| **안 찍은 것** | 라벨을 모을 때. 기본값 |
| **사전과 어긋남** | 사전을 고칠 때. 여기 모인 글이 곧 고칠 목록 |
| **찍은 것** | 내가 뭘 찍었는지 되짚을 때 |
| **전부** | 거르개 없이 |

`data/labels.jsonl` 에 한 줄씩 붙습니다. 나중 줄이 이기므로 고쳐 찍어도 앞줄을 지울 필요가 없습니다.
손으로 모은 것이라 다시 만들 수 없습니다 — `data/` 는 git 에 안 들어가니 [볼륨 백업](DOCKER.md#볼륨)으로 챙기세요.

```
node tools/eval-lexicon.mjs
```

홀드아웃 12,000건과 직접 찍은 것을 따로 채점합니다. 사전을 고치고 다시 돌려 비교합니다.
직접 찍은 쪽은 어긋난 글만 골라 찍기 때문에 홀드아웃보다 낮게 나오는 것이 정상입니다.

## 서버가 필요한 이유

토스 API가 `Origin` 헤더가 붙은 요청을 거절합니다.

```
헤더 없음 (서버)              200
Origin: 아무 사이트           403
Origin: tossinvest.com       200  ACAO: https://www.tossinvest.com
```

브라우저는 교차 출처 요청에 `Origin`을 반드시 붙이고 JS로 바꿀 수 없습니다. 그래서 정적 호스팅(GitHub Pages 등)만으로는 실시간·봉·글 어느 것도 못 받습니다. Node가 대신 부르고 결과만 넘깁니다.

## 접근 제한

서버를 처음 켜면 `.access-key`가 생깁니다. 링크에 `?k=` 로 붙습니다.

```
http://localhost:8731/?k=...
```

키가 없으면 **모든 경로가 404**입니다 — 있는지조차 알려주지 않습니다. 첫 요청에 키가 맞으면 쿠키를 심어 이후 요청은 파라미터 없이 통과합니다.

키가 새면 `.access-key`를 지우고 재시작하면 됩니다. 이전 링크가 전부 죽습니다.

## 한계

- **토스 내부 API입니다.** 문서화된 계약이 아니라 언제든 바뀔 수 있고, 바뀌면 수집이 오류로 죽습니다.
- **정답지가 사람이 아닙니다.** 라벨 15,573건을 SLM이 찍었습니다. 분류기는 그 모델의 눈을 물려받습니다 — 그 모델이 틀린 자리는 같이 틀립니다. 사람이 읽어 확인한 건 240건뿐이고, 거기서 SLM 정확도는 68.8% 였습니다.
- **분류기는 부정을 과하게 부릅니다.** 사람 자에서 부정 정밀도 53.0%. 사람이 중립으로 본 글의 절반 가까이를 부정으로 부릅니다. 사전이 65% 흘려보내던 걸 14%로 줄인 대가입니다.
- **공포어는 여전히 사전입니다.** 반어법과 신조어를 놓칩니다. 부정어가 뒤에 오면("손절 안 했다") 놓칩니다. 다만 기준선을 같은 채점기로 계산하므로 오탐이 평균에 섞여 z에서 차감됩니다. 보는 건 절대 수준이 아니라 변화입니다.
- **개수 기반이라 글이 몰리기만 해도 오릅니다.** 그래서 툴팁에 `글 / 공포`를 같이 띄웁니다.
- **상관은 인과가 아닙니다.** 공포지수가 먼저 튀었다고 그게 주가를 예고한 건 아닙니다.
