지금 auto/ui 브랜치의 별도 작업칸이다. 여기서 live.html 의 폰(390x844) 화면을 혼자 고친다.
앞선 여섯 판은 main 에 합쳐졌고 이 작업칸도 그 위에 올라와 있다. 아래 수치는 합친 뒤 다시 잰 것이다.

재 놓은 것 (390x844, 종목 6개, 앞 세 판까지 반영):
  실시간 탭 — 차트 위 395px · 봉 380px · 거래량 778~824px(첫 화면 안, 여유 20px) · 문서 1485px
  글 탭   — 글 첫 줄 284px · 문서 8204px
  어두운 화면 — --faint 를 #828c9a 로 밝혀 대비 4.77. 봉 색은 5.42/6.64 로 문제 없음.

대기열 — 위에서부터 하나씩. 이미 된 것은 건너뛴다:
  1. 밝은 팔레트의 대비를 올린다. 사람이 (나) 안을 골랐다: --muted 도 같이 내린다.
     --muted #71717a -> #64646d, --faint #9a9aa3 -> #75757f 로 가되, 정확한 값은 네가
     재서 맞춰라. 조건은 둘이다 — (a) --faint 가 칠해진 네 자리(카드 #ffffff, 지면
     #f7f7f8, 고른 줄 #e8f3ff, 칩 #f1f1f3) 에서 전부 4.5 이상, (b) --faint 가 --muted
     보다 흐린 순서 유지. 앞 판에 네가 잰 값: faint 카드 2.79 / 지면 2.61 / 고른줄 2.48,
     muted 카드 4.83 / 지면 4.51. 색조는 그대로 두고 밝기만 내린다. 다른 색은 건드리지 마라.
  2. 손으로 고르는 어두움의 --faint 도 밝힌다. 사람이 승인했다. live.html:95 근처
     data-theme="dark" 쪽 --faint 가 #5c5c66 이고 카드 #101012 위에서 대비 2.87 이다.
     앞 판에 prefers-color-scheme: dark 쪽만 고쳐서 이쪽이 남았다. 같은 기준(4.5)으로
     맞추고, 그쪽 --muted 와의 순서도 함께 확인해라.
  3. 글 한 장을 잰다. 문서가 8204px 인데 글 카드 한 장이 몇 px 인지, 한 화면에 몇 개가
     들어오는지 모른다. 재고 나서 가장 큰 한 가지만 고쳐라.

끝난 것 — 다시 하지 마라:
  느린 폰 첫 그림. 이미 쟀고 줄일 것이 없었다. 긴 작업 254ms 의 속은 Layout 223ms 이고
  우리 JS 는 15ms 다. 따뜻해진 뒤 paint 는 29.6ms — 한 번뿐인 최초 배치 비용이다.
  content-visibility: auto 는 270ms 로 더 나빴고, 숨은 카드 건너뛰기는 차이가 없었다.
